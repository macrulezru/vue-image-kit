## [1.1.0] - 2026-08-20

### Added

- GitHub Actions CI workflow — runs lint, typecheck, tests and build on every push/PR to `master` across Node 18/20/22.
- `CONTRIBUTING.md` with local setup, scripts and PR guidelines.
- End-to-end tests (Playwright) covering `VImage` in a real browser: IntersectionObserver-driven lazy loading, `<picture>` AVIF/WebP source switching, and blur-up placeholder transitions.
- `VImage`'s new `image` prop consumes CLI manifest entries / `?vik` build-time imports directly (`<VImage :image="meta" alt="…" />`), seeding `src`/`width`/`height`/`blurhash`/`thumbhash`/`placeholder`/`sizes` — any explicit prop still overrides the matching field. `useImage()` gained a matching `rawSrcset` option so a pre-built manifest `srcset` string is used as-is instead of being regenerated from `widths`.
- `VImage`'s new `priority` prop is a shorthand for the LCP/hero image — forces `lazy=false`, `fetchpriority='high'`, `decoding='sync'` in one prop instead of three. Documented as an explicit marker, not automatic LCP detection.
- CLI/Vite-plugin pipeline now handles `.svg` (copied through untouched, already resolution-independent) and animated `.gif` (copied through as the fallback, plus an animated WebP re-encode when `webp` is in `--formats`) instead of silently skipping them. `SUPPORTED_EXTS` is now exported once from `src/cli/processor.ts` and imported by the Vite plugin instead of being duplicated.
- New `useNetworkAware()` composable (+ non-reactive `isSaveDataEnabled()`) wraps the Network Information API's `saveData`/`effectiveType`. `useImagePreloader()` now skips `preload()` on a save-data connection. `VImage`'s new `respectSaveData` prop neutralizes `priority` and downgrades `src` to the smallest available URL (`densities` map or `image.srcset`) on a save-data connection.
- `VImage`'s new `layout` prop (`'fixed' | 'responsive' | 'fill'`) switches the wrapper sizing strategy — exact box, container-filling with auto-generated `sizes`, or absolute fill of a positioned parent. Unset keeps the existing default behavior unchanged.
- `sources` (art direction breakpoints) now accepts a `{ avif?, webp?, fallback }` object per breakpoint, not just a plain URL — combine a different crop *and* different formats per breakpoint instead of only one or the other.
- New `autoLoader()` in `vue-image-kit/cdn` detects 8 of the 12 CDN adapters directly from a URL's hostname (Cloudinary, imgix, Bunny, ImageKit, Sanity, Storyblok, Contentful, Gumlet); the remaining 4 "your own domain" providers (Netlify, Vercel, Cloudflare, TwicPics) opt in via `config.hosts`. Unrecognized hosts pass through unchanged.
- The CLI/Vite-plugin `generate()` pipeline now prints a detailed per-image report as it works — source path/format/dimensions/size, then every output variant's own path/format/dimensions/size (flagged `(existing)` under `--skip-existing`, `(dry-run — not written)` under `--dry-run`) — replacing the old single-line `N/M filename` progress overwrite. `ProcessedVariant` gained `height`/`sizeBytes`/`skipped`; `ProcessedImage` gained `originalFormat`/`originalSizeBytes` to support it (`src/cli/report.ts`). The batch summary at the end now also reports total input/output size and how much the smallest available format saves vs. the original on average.
- `npm run check:size` (`scripts/check-bundle-size.cjs`) fails the build when a shipped browser bundle's gzip size exceeds its budget; wired into CI right after `npm run build`.
- `VImage` now warns (`console.warn`, dev builds only) when `alt` looks like a mistake — missing, whitespace-only, or filename-shaped (e.g. `"photo.jpg"`). A deliberate `alt=""` (the documented way to mark a decorative image) never triggers it. Uses `process.env.NODE_ENV`, not `import.meta.env.DEV`, so the check survives this package's own build and is correctly evaluated by the consuming app's bundler instead of being permanently inlined to `false`.
- E2E coverage for `layout` (`fixed`/`responsive`/`fill`) and `priority` — new `demo` tab ("Layout & priority") plus `e2e/layout-fill.spec.ts` and `e2e/priority.spec.ts`, verifying real browser CSS layout and real `fetchpriority`/`decoding` attributes that jsdom unit tests can't check.
- New `autoSrcset()` in `vue-image-kit/cdn` — same hostname detection as `autoLoader()`, but builds a real per-width `srcset` via the resolved adapter's own `.srcset()` instead of a single URL. `VImage`'s new `cdn` prop (`boolean | AutoLoaderConfig`) wires both straight into the component: a string `src` on a recognized CDN host gets rewritten automatically, and combined with `widths` each candidate gets its own CDN-transformed URL instead of `widths`' usual same-URL-every-candidate behavior. Trade-off: importing CDN detection into `VImage.vue` pulls all 8 hostname-fingerprinted adapters into the main bundle unconditionally, whether or not `cdn` is ever used — main ESM bundle grew ~2.2 kB gzip (10.8 → 13.0 kB). Accepted as worth it for the DX win; the `check:size` budget from 5.1 (raised to 15/13 kB) is what caught the real number, which was larger than the initial in-progress estimate.
- `VImage`'s new `loader="server"` prop (+ `loaderRoute` override) is the local-server counterpart to `cdn` — builds request URLs against `vue-image-kit/server`'s on-demand handler via `buildImageUrl()`, same "plain-string src, upgrades `widths` to real per-candidate URLs" shape. Resolves its route via a new `useServerRoute()` composable (plugin/Nuxt-module default → per-component override), plumbed through a new `SERVER_ROUTE_KEY` provide/inject, mirroring how `breakpoints` already works. `cdn` wins if both are set on the same image.
- Nuxt module: new `onDemandServer` option registers the on-demand handler as a real Nitro server route via `@nuxt/kit`'s `addServerHandler` — `true` for defaults (root `public/`, route `/_vik/image`) or an object to override `root`/`cacheDir`/`maxAge`/`allowedWidths`/`maxWidth`/`route`. The route is also threaded into the client plugin as `loader="server"`'s default automatically. Initially shipped without a live Nuxt check (this repo had no Nuxt project to test against) — closed by the new `demo-nuxt/` app below: real `nuxt dev` and `nuxt build` runs confirmed the Nitro route actually resizes (verified output dimensions/content-type), the cache lands under the configured `root`, and `loader="server"` renders the right per-width URLs in server-rendered HTML.
- New `demo-nuxt/` — a separate, minimal Nuxt 3 app (`npm run demo:nuxt` / `demo:nuxt:build`) aliased straight to `src/`, for exercising what the plain-Vite `demo/` can't: module registration + `breakpoints`, auto-imported composables/utilities with zero explicit imports, `onDemandServer`'s real Nitro route, and SSR-rendered `<VImage>` (`isSSR` branch) output. Not part of the e2e/CI loop (see `todo.md` 5.9) — a manual check, same spirit as this whole release's "verify past the mocks" approach.
- New `vue-image-kit/server` entry point: `createImageHandler({ root, ... })` is a framework-agnostic Node request handler that resizes/re-encodes images on request (jpg/png/webp/avif → jpg/webp/avif/png), disk-caches the result, and enforces path-traversal protection — for self-hosted setups with no CDN. Plus `buildImageUrl()` to construct request URLs. The Vite plugin's new `dev.onDemand` option mounts the same handler as dev-server middleware (`/_vik/image` by default) so images resize on request during `vite dev` without a batch CLI run; never active during `vite build`.
- New `incremental` mode for `generate()` (CLI `--incremental`/`--no-incremental`, or the `incremental` config/Vite-plugin option): skips reprocessing a source whose mtime matches a persisted record from the last run (falling back to a content hash when mtime differs, so an unmodified file survives a git checkout without a needless reprocess), instead of `buildStart`/`handleHotUpdate`/`--watch` re-scanning and reprocessing every source on every single-file change. State persists to `<output>/.vik-incremental.json`, including each skipped image's full metadata so the batch report/manifest stays complete. A config change (widths/formats/quality/etc.) invalidates everything at once. Auto-enabled under `--watch` and during `vite dev` (not `vite build`) unless set explicitly either way; off by default for a one-shot `generate`. Verified against the real built CLI (not just unit tests) across four scenarios: nothing changed, one file changed, config changed, `--watch` auto-enabling it without the flag.

### Fixed

- `src/components/VImage.vue`'s `mergedSrc` computed built a `{ avif, webp, fallback }` object with `avif`/`webp` explicitly assigned `undefined` when absent, which violates `exactOptionalPropertyTypes` for the `SrcSet` type — a latent bug since Phase 1 that `tsc --noEmit` never caught because plain `tsc` doesn't deeply type-check `.vue` SFC script content (it needs `vue-tsc` or, as it turns out, `vite-plugin-dts`'s own `@vue/compiler-sfc`-based extraction during a real build). Surfaced only once `npm run build` was run again after unrelated changes. Takeaway: a clean `tsc --noEmit` on this project does not guarantee `.vue` files are actually free of type errors — a full build is the real check.
- `vite.nuxt.config.ts` didn't mark `sharp` or `node:*` builtins as external, so adding a Node-only file to the Nuxt module's build graph (`server-handler.ts`, `node:path` in `module.ts`) pulled `sharp`'s entire JS wrapper (and its `detect-libc` dependency) into a 197 kB chunk shipped as part of `dist/nuxt/`. Added `sharp` and `/^node:/` to that config's `external` list, matching `vite.server.config.ts` and `vite.plugin.config.ts`.
- `src/server/handler.ts`'s passthrough response (no `w`/`format` requested) always sent `Content-Type: application/octet-stream` instead of the real MIME type — `mimeFor()` looked up `extname()`'s result (which includes the leading `.`) directly against a table keyed without dots. Caught via a live `vite dev` + `curl` check, not just the mocked unit tests.
- README ("Vite plugin → Build-time imports"): the `?vik` example manually bound `:srcset="meta.srcset"` onto `<VImage>`, a prop that doesn't exist on the component (srcset is generated internally from `widths`/`densities`, never accepted directly) — replaced with the new `image` prop.
- `eslint.config.js`: the test-file override matched a nonexistent `src/__tests__/**` path instead of the actual `test/**` directory, so real test files were linted under the stricter `src/**` ruleset (causing false-positive `no-unused-vars` errors and `one-component-per-file` warnings).
- `scripts/fix-cli-shebang.cjs` had no Node/CommonJS environment in ESLint, causing `no-undef` errors on `require`, `__dirname`, `process` and `console`.
- `no-console` is now allowed in `src/cli/**` (console output is the CLI's actual product, not debug noise) instead of being warned on at every call site.
- Removed an unused `_options` parameter and unused test imports flagged once the test-file lint override was corrected.
- Replaced `as any` in `test/setup.ts` and `Record<string, any>` in `src/nuxt/runtime/app.d.ts` with precise types; updated `src/nuxt/runtime/plugin.ts` to narrow the now-`unknown` runtime-config value instead of relying on `any`.
- `demo-nuxt/` had no `tsconfig.json` (normally scaffolded by `nuxi init`, skipped since the app was hand-written), so neither the IDE nor `tsc` could see Nuxt's auto-generated auto-import/module types — surfaced as `Cannot find name 'generateSrcset'/'buildSizes'/'useImagePreloader'/'ref'/'defineNuxtConfig'` in `pages/index.vue` and `nuxt.config.ts`. Added `demo-nuxt/tsconfig.json` extending `.nuxt/tsconfig.json`. Fixing this also surfaced two more errors that had never been checked before: `src/nuxt/module.ts`'s runtime-config assignments needed casting to `Record<string, unknown>` (Nuxt infers `RuntimeConfig.public.vueImageKit`'s type from the literal object a consuming `nuxt.config.ts` writes, which can be narrower than `PublicConfig`), and `demo-nuxt/nuxt.config.ts` needed to alias `vue-image-kit` via Nuxt's own top-level `alias` option instead of `vite.resolve.alias` (only the former propagates into the generated `.nuxt/tsconfig.json` `paths`) plus a new `demo-nuxt/shims.d.ts` referencing `src/env.d.ts` (for the `*.vue` ambient module shim, otherwise unreachable through `.nuxt/tsconfig.json`'s `include`). Re-verified with a fresh `nuxt build` + a real running production server (SSR 200, on-demand resize route confirmed producing real 280×187 output) to confirm the type-only fix didn't regress runtime behavior.
- `demo-nuxt`'s `nuxt dev` printed repeated `Pre-transform error: Failed to resolve import "#app-manifest"` on every cold start — Vite's own `server.warmup.clientFiles` (set internally by Nuxt to the app entry) pre-transforms it before Nitro's `nitro-server` module has registered the real `#app-manifest` alias, racing it. Harmless (that import sits behind a dead `if (false)` branch in `nuxt/dist/app/composables/manifest.js`; real requests resolve fine once the dev server is up — confirmed via direct `curl` of the module and the SSR page) but noisy. Since `vite.server.warmup` in `nuxt.config.ts` gets array-merged with Nuxt's own entry rather than replacing it, cleared it in a `hooks['vite:extendConfig']` callback (only place that runs after the merge) instead.
- `npm run typecheck` never checked `src/nuxt/**` — `tsconfig.json` excludes it and `tsconfig.cli.json` only covers `src/cli`. A real type error there (surfaced while tightening the `any` above) was silently swallowed by `vite-plugin-dts` during `build:nuxt` instead of failing the build. `tsconfig.nuxt.json` (previously only used for declaration output) is now wired into `typecheck` and CI.
- README's bundle-size claims (`~6.8 kB gzip` in the intro, `~3.8 kB gzip` in the features list, and a stale table) no longer matched the actual build output (`VImage.vue` grew substantially across this release). Replaced hardcoded numbers in prose with a link to the one table that's now enforced by `npm run check:size` in CI.

## [1.0.6] - 2026-06-24

Initial public release.

### Added

- `<VImage>` component: lazy loading via a shared `IntersectionObserver` pool, WebP/AVIF `<picture>` switching, responsive art direction (`sources`/`breakpoints`), `srcset`/`sizes` and density (`1x`/`2x`/`3x`) generation, focal point cropping, error retry with exponential backoff, and an `#error` slot.
- Placeholders: Blurhash (in-house decoder, canvas-rendered), ThumbHash (PNG data URL, alpha-aware), LQIP base64 blur-up, solid average-color, and animated shimmer — plus `encodeBlurhash()`/`encodeThumbHash()` for client-side UGC previews.
- Headless composables: `useImage`, `useBlurhash`, `useLazyLoad`, `useBreakpoints`, `useImagePreloader`, `useBackgroundImage`.
- `v-lazy-img` directive for lazy background images.
- CLI (`vue-image-kit generate`) — resizes source images, emits JPG/WebP/AVIF variants, generates LQIP/Blurhash/ThumbHash, writes a typed manifest, supports `--watch` and `--dry-run`.
- CDN URL builders for 12 providers: Cloudinary, imgix, Bunny, Sanity, Storyblok, Contentful, Vercel, Cloudflare, ImageKit, TwicPics, Netlify, Gumlet.
- Nuxt 3 module with auto-imports and a Vite plugin for build-time `?vik`/`?thumbhash` imports.
- Full TypeScript types, SSR-safe rendering, zero runtime dependencies, tree-shakeable (`sideEffects: false`).
